# Aurora Commerce 10 分钟演示脚本

## 演示前 5 分钟

1. 执行 `docker compose up -d`，确认所有服务 healthy/running。
2. 执行 `SMOKE_BASE_URL=http://localhost:3000 npm run smoke`，保留成功输出。
3. 打开商城 `http://localhost:3000` 和运营后台 `http://localhost:3001`。
4. 准备管理员 `admin@aurora.local` / `Aurora@2026`，客户账号现场注册。

## 0:00–1:00 产品定位

- 展示首页视觉、分类、精选商品和内容入口。
- 说明这是“核心交易真实闭环、外围能力可演示、模块边界可扩展”的 Web 电商基座。
- 强调页面数据来自真实 API 与数据库，不是静态页面拼图。

## 1:00–2:30 发现与互动

- 进入发现频道，展示内容流、推荐理由和行为反馈。
- 注册客户账号，收藏一个商品。
- 领取优惠券，展示未领取、可用、锁定/已用等状态承载能力。

## 2:30–4:30 核心交易

- 商品加入购物车，修改数量并进入结算预览。
- 展示商品金额、优惠、运费和应付金额由后端统一计算。
- 创建订单并完成模拟支付，打开订单时间线和消息中心。

## 4:30–6:00 运营履约

- 切换运营后台并登录。
- 展示真实聚合的 GMV、待发货、已完成、待售后和库存预警。
- 在订单工作台找到刚创建的订单并发货，填写承运商和运单号。

## 6:00–7:15 客户收货与评价

- 回到商城刷新订单，查看物流轨迹并确认收货。
- 对真实购买的订单项发表五星评价。
- 回到运营端评价页回复该评价，说明评价校验、唯一约束和乐观锁保护。

## 7:15–8:30 售后闭环

- 另选一个已支付订单提交仅退款，或对已收货订单申请退货退款。
- 在运营端审核申请，展示售后时间线、订单 `REFUNDING/REFUNDED` 状态以及库存幂等回补。
- 说明重复退款不会重复入账或重复增加库存。

## 8:30–9:15 信息推流

- 展示站内通知和未读数。
- 说明支付、发货、售后等事件经 SSE 实时推送到 Web 端，断线后仍可从通知中心恢复查看。

## 9:15–10:00 AI 高效研发证据

- 展示 `docs/stages` 中逐日验收记录和 `docs/reviews` 中每阶段 Review 闭环。
- 展示后端自动化测试、前端生产构建、端到端 smoke 输出。
- 打开 GitHub Actions Quality Gate，说明每阶段都完成“开发—Review—修复—回归—推送—CI”。
- 以模块化单体、Flyway 数据模型和 `prod`/`demo` Profile 隔离说明后续演进路径。

## 演示失败时的降级顺序

1. 页面操作异常时立即展示刚执行成功的 `npm run smoke` 输出。
2. 外部图片加载慢时继续展示业务数据和交易链路，不等待图片。
3. 单个页面状态被上次演示数据影响时注册新客户；冒烟脚本本身每次使用唯一账号。
4. 网络无法访问 GitHub 时展示本地 Review 和回归报告，避免阻塞主体演示。
