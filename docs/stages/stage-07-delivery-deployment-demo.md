# Stage 07：部署、演示与最终交付

## 阶段目标

把 Day 1–Day 6 的业务能力收束为可一键部署、可重复验收、可在 10 分钟内完整讲解的交付包，并把核心交易冒烟加入持续集成。

## 交付范围

- Spring Boot 多阶段镜像：构建阶段产出 JAR，运行阶段使用非 root 用户和容器健康检查。
- 商城与运营端多阶段镜像：Node 构建，Nginx 托管 SPA 并同源代理 `/api`。
- Docker Compose：MySQL、后端、商城、运营端按健康依赖编排，数据卷持久化。
- 环境隔离：新增 `demo` Profile，与 `prod` 组合时才向 MySQL 加载演示数据和管理员。
- 自动化冒烟：覆盖健康、首页、注册、收藏、购物车、结算、订单、支付、发货、收货、评价和运营看板。
- CI 门禁：Compose 静态解析及真实后端进程的核心交易冒烟。
- 交付材料：部署手册、演示脚本、最终回归报告和本阶段 Code Review。

## 验收条件

- `docker compose config --quiet` 成功。
- 使用 `.env` 可构建并启动四个服务，前端通过 `/api` 访问后端。
- `npm run smoke` 可重复运行，每次创建独立客户和订单。
- 本地后端测试、双端生产构建、Diff 检查全部通过。
- 商城和运营后台完成最终浏览器验收。
- Stage 07 Code Review 的 P0/P1 问题清零。
- 代码推送 GitHub，Quality Gate 全部 job 成功。

## 关键决策

- Demo 数据必须由 `demo` Profile 显式开启，避免生产 Profile 意外创建弱口令管理员。
- Nginx 使用服务名 `backend` 代理，前端仍保持相对 API 路径，部署无需重新构建环境 URL。
- 冒烟工具使用 Node 原生 `fetch`，不新增运行依赖，也不要求机器安装 `jq`。
- 冒烟每次使用时间戳加随机后缀，避免用户邮箱、幂等键和物流单号冲突。

## 不在本阶段范围

- 公网 HTTPS、云资源 IaC、日志平台与 APM。
- 真实支付、短信、物流和对象存储供应商。
- Kubernetes、多活容灾、压测容量承诺。

这些属于从 Demo 基座进入生产化时的下一阶段工作，不影响本次一周 Demo 的验收。
