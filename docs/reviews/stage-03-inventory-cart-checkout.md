# Stage 03 库存、购物车与结算预览 Code Review

## 审查范围

- Flyway 库存、库存预占、库存流水和购物车数据结构
- 库存查询、调整、原子预占、释放与业务键幂等
- 购物车增删改、用户隔离、商品/库存失效状态和结算预览
- 商品目录与库存模块公开 Facade 契约
- 商城快捷加购、购物车抽屉、数量/勾选/删除和金额展示
- Stage 03 自动化测试与运行态浏览器验收

## Review 发现

| 级别 | 发现 | 处理结果 |
|---|---|---|
| P1 | 库存批量更新启用 `clearAutomatically` 后会把已加载的预占记录移出持久化上下文，释放状态可能不落库，重复释放会再次扣减预占量 | 取消自动清空持久化上下文，并新增重复释放回归测试，确认释放保持幂等 |
| P1 | 预占库存若采用“先查余量、再更新”会在并发请求下发生超卖 | 改为带可售库存条件的数据库原子更新，并通过两个请求争抢最后一件库存的并发测试 |
| P2 | 登录/注册成功后同步等待购物车加载，购物车接口临时失败会把已成功认证误显示为登录失败 | 认证成功立即关闭弹窗，购物车改为后台加载并在购物车区域独立承载错误 |
| P2 | 商品卡片显示价与快捷加购 SKU 若分别取最低值，可能来自不同 SKU，造成展示与加购价格语义不一致 | 明确选择最低销售价 SKU 作为默认 SKU，并从同一 SKU 读取销售价和市场价 |
| P2 | 购物车若直接依赖商品和库存模块的 Repository，会扩大模块耦合并阻碍后续拆分 | 增加 `CatalogFacade` 与 `InventoryFacade` 公开契约，购物车仅通过契约跨模块协作，模块边界测试通过 |

## 验证结果

- 后端：`mvn test` 通过，共 11 个测试；包含模块边界、权限、购物车、金额、运费、库存不足、并发防超卖、预占及释放幂等。
- 前端：`npm ci` 通过，依赖审计 0 个漏洞；商城端和运营端生产构建通过。
- 浏览器：注册、快捷加购、购物袋数量更新、数量修改与结算预览闭环通过；¥858 商品金额正确命中免运费，控制台无错误或告警。
- Diff：`git diff --check` 在提交前执行并确认。
- GitHub Actions：推送后确认 Quality Gate。

## 已知限制

- 本阶段只生成结算预览，不创建订单，也不实际占用购物车库存；Stage 04 将在订单创建时复用库存预占能力。
- 运费使用统一演示规则，尚未接入收货地址、区域模板和配送渠道。
- 库存是单仓模型，尚未支持多仓分配、调拨和在途库存。
- 购物车冲突依赖数据库唯一约束和乐观锁兜底；高并发购物车合并将在后续阶段按需要增强重试策略。
