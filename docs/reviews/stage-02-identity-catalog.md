# Stage 02 身份、商品与首页数据化 Code Review

## 审查范围

- Flyway 身份、商品、SKU、Banner 数据结构及演示数据
- 注册、登录、JWT、当前用户与角色权限
- 商品查询、首页聚合和管理员商品维护 API
- 商城首页 API 接入、注册登录和会话恢复
- Stage 02 集成测试与运行态浏览器验收

## Review 发现

| 级别 | 发现 | 处理结果 |
|---|---|---|
| P1 | 演示数据与正式 Schema 位于同一迁移，未来生产库会被写入样例商品 | 拆分为公共 Schema 与仅 `local` Profile 加载的演示数据迁移 |
| P1 | 演示管理员默认初始化没有 Profile 隔离 | 初始化器限制为 `local`，`prod` 强制关闭并要求外部数据库/JWT 配置 |
| P1 | 商品创建未校验 SKU 编码重复及市场价与销售价关系 | 增加领域校验，非法数据在入库前返回明确错误 |
| P2 | JWT 服务存在两个未标注构造器，导致 Spring 无法确定注入入口 | 收敛为单一构造器并通过上下文测试 |
| P2 | `127.0.0.1` 本地页面被 CORS 拒绝，而默认配置仅允许 `localhost` | 同时允许两种本地回环 Origin，生产值可通过环境变量覆盖 |
| P2 | API 客户端假设所有响应均为 JSON，代理或网关错误会暴露解析异常 | 先读取文本并安全解析，非 JSON 响应转换为稳定错误码和文案 |
| P2 | 浏览器禁用 Session Storage 时登录成功后仍会被当作失败 | 存储读写降级为内存会话，避免阻断登录 |
| P2 | 登录后缺少可发现的退出入口 | 新增账户菜单与退出登录操作 |
| P2 | 商品卡片聚合使用通用运行时类型分支，可读性差 | 改为 Category/Brand 显式映射，保持批量查询且避免 N+1 |
| P2 | Spring Security 的 401/403 没有统一 JSON 错误体，前端无法稳定识别 | 认证入口和拒绝处理器统一返回标准 `ApiResponse` |

## 验证结果

- 后端：`mvn test` 通过，共 8 个测试，覆盖上下文、模块边界、统一鉴权错误、注册登录、JWT、首页数据、角色隔离、商品创建、价格约束与上架闭环。
- 前端：`npm ci` 通过，依赖审计 0 个漏洞；商城端和运营端生产构建通过。
- 浏览器：首页真实数据和管理员登录闭环已通过。
- Diff：`git diff --check` 通过。
- GitHub Actions：推送后确认。

## 已知限制

- 访问令牌暂存在 Session Storage；正式产品建议改为短期访问令牌配合 HttpOnly Refresh Cookie。
- 当前未实现登录限流、邮箱验证、密码找回和令牌刷新。
- 商品图片与字体仍依赖外部 CDN，正式演示前应准备本地静态资产。
- 商品管理页面将在运营后台后续阶段接入，本阶段已经提供完整受保护 API。
