# Stage 05 营销、内容、推荐与消息 Code Review

## 审查范围

- 优惠券活动、领取、试算、下单锁定、支付核销、取消和超时释放
- 订单优惠总额与商品行优惠分摊的一致性
- 内容 Feed、文章发布、推荐行为采集和可解释排序
- 站内消息、未读状态、事务提交后 SSE 推送和前端断线恢复
- 用户数据隔离、管理接口授权、输入校验和模块边界
- 商城发现频道、领券、推荐加购、内容阅读、优惠结算和消息中心
- Stage 05 自动化测试与运行态浏览器验收

## Review 发现

| 级别 | 发现 | 处理结果 |
|---|---|---|
| P1 | `order_discounts.user_coupon_id` 被错误设置为唯一键。订单取消后用户券虽恢复为 `AVAILABLE`，再次下单仍会因旧的 `RELEASED` 优惠记录触发唯一键冲突 | 移除用户券唯一约束，保留订单号唯一约束；券本身继续用悲观锁保证同一时刻只能锁定一个订单，并新增“取消后重新下单、再次取消”回归测试 |
| P2 | SSE 连接超时或网络中断后前端不会重连，用户只能刷新页面才能恢复实时消息，且断线期间的消息可能遗漏 | 增加 1 秒起步、最高 30 秒的指数退避重连；每次重连前重新拉取消息中心以补齐断线期间消息，主动退出时可立即终止等待 |
| P2 | SSE 前端解析只识别 `\n\n`，若代理或服务器输出 CRLF 分隔会无法拆帧 | 帧和行解析同时兼容 LF 与 CRLF；本地真实 SSE 推送继续通过 |
| P2 | 优惠分摊测试只覆盖单商品，无法防止多商品取整后行优惠合计偏离订单优惠 | 增加两商品分摊断言：按比例向下取整，最后一行承接余数，并直接校验全部商品行优惠合计等于订单优惠 `50.00` |

## 验证结果

- 后端：`mvn test` 通过，共 17 个测试；覆盖模块边界、内容发布、匿名和个性化推荐、领券幂等、跨用户隔离、锁券/核销/释放/再次使用、多商品优惠分摊、通知未读状态、SSE 建连和管理权限。
- 前端：`npm ci` 及根目录 `npm run build` 通过；商城端和运营端生产构建成功。
- 浏览器：真实完成注册、发现频道浏览、领取新会员券、推荐/内容展示、¥2,499 商品结算、优惠 ¥50、实付 ¥2,449、模拟支付和订单中心闭环；未读消息通过 SSE 从 1 实时增加到 3，页面视觉布局无明显错位。
- Diff：`git diff --check` 在提交前执行并确认。
- GitHub Actions：推送后确认 Quality Gate。

## 已知限制

- 推荐排序是 Demo 级规则模型，候选集和最近行为均设置了小规模上限；后续可替换为离线特征、向量召回和在线排序服务。
- SSE 连接状态保存在单实例内存中，多实例部署需要增加 Redis Pub/Sub、消息队列或专用推送网关。
- 内容正文当前采用纯文本，未包含富文本安全清洗、版本管理、定时发布和内容审核工作流。
- 优惠券暂只支持固定金额满减和每人一张，后续可扩展折扣券、品类/商品范围、会员等级、人群包和叠加规则。
