# Stage 04 订单、支付与履约 Code Review

## 审查范围

- 订单、订单快照、状态日志、支付单、回调、物流单和轨迹数据结构
- 下单、库存预占、支付扣库、取消/超时释放的事务一致性
- 下单、支付、发货和确认收货幂等行为
- 用户订单隔离、管理接口授权和输入校验
- 购物车、订单、支付、库存和履约模块边界
- 商城结算、模拟收银台、订单列表、状态时间线和物流信息
- Stage 04 自动化测试与运行态浏览器验收

## Review 发现

| 级别 | 发现 | 处理结果 |
|---|---|---|
| P1 | 超时任务先加载订单实体再等待悲观锁，若等待期间支付成功，持久化上下文可能保留旧状态并尝试错误关闭订单 | 超时扫描只读取订单号，逐单加写锁后重新加载并再次判断状态和截止时间 |
| P1 | 下单读取购物车快照时未锁定购物车行，并发修改数量可能造成订单快照与被删除的购物车状态不一致 | 下单专用查询对已勾选购物车行加悲观写锁，并在同一事务中校验、建单和清理 |
| P1 | 重复创建支付单时先校验订单必须待支付，已支付订单重试会在返回原支付单前被状态校验拒绝 | 支付目标契约返回订单状态，服务先查找原支付单；存在时直接幂等返回，不存在时才校验状态 |
| P2 | `OrderFacade` 同时保留生产构造器和测试时钟构造器，Spring 无法确定注入入口 | 收敛为单一注入构造器，时钟作为内部 UTC 时钟，并通过应用上下文测试 |
| P2 | 乐观锁冲突没有统一 API 响应，购物车或订单并发修改可能退化为不稳定的 500 响应 | 增加 `CONCURRENT_MODIFICATION` 统一 409 错误响应，提示客户端刷新重试 |
| P2 | 在订单列表选择待支付订单时自动弹出收银台，用户无法先查看详情或选择取消 | 选择订单仅展示详情，支付改为详情页显式操作 |
| P2 | 库存预占公开契约未处理空 Map、空 SKU 或空数量，错误输入可能产生空指针异常 | 完整校验业务键、Map、SKU 和数量并返回稳定业务错误 |

## 验证结果

- 后端：`mvn test` 通过，共 14 个测试；包含模块边界、订单快照、权限隔离、防重复下单、重复支付、取消/超时释放、支付扣库、重复发货和重复确认收货。
- 前端：`npm ci` 通过，依赖审计 0 个漏洞；商城端和运营端生产构建通过。
- 浏览器：真实加购、结算预览、地址填写、创建订单、模拟支付和订单中心闭环通过；¥429 金额全程一致，控制台无错误或告警。
- Diff：`git diff --check` 在提交前执行并确认。
- GitHub Actions：推送后确认 Quality Gate。

## 已知限制

- 当前支付和物流均为可替换的 Mock 实现，未接入外部渠道签名、验签和异步通知重试。
- 超时关闭由单进程定时扫描触发；多实例部署可依赖现有行锁保证正确性，后续建议改为分片任务或延迟消息。
- 订单列表采用 Demo 级全量查询，数据规模增长后需要补充分页和查询索引组合。
- 本阶段不处理退款、退货和逆向库存，统一在 Stage 06 售后闭环实现。
